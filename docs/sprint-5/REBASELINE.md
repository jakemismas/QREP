# Sprint 5 re-baseline record

This is the closed record of what sprint 5 retires and re-expresses: every test at commit 834d8be
by file::test id, every frozen literal with its freeze-record issue, and every superseded or
suspended criterion with its replacement. It binds once the governance PR for issue #106 merges;
CLAUDE.md and docs/SPEC.md point here. Why a closed record: sprint 5 deletes the automatic
detector, the editor and engine dead code together with hundreds of their tests (HANDOFF 2.3), and
a list that names each one keeps that deletion from becoming a way to weaken anything else.

The tables between `rebaseline:begin` and `rebaseline:end` markers are generated by
scripts/rebaseline_inventory.py; never edit them by hand, because `--check` then fails. The
literal, criteria and policy sections are written by hand.

In this file, "HANDOFF n" means section n of the sprint-5 setup handoff, the record of Jake's
decisions of 2026-10-06 that docs/SPEC.md turns into the product contract. Ticket ids (A1, B6b,
C3c and so on) are the sprint-5 tickets in docs/sprint-5/qrep-sprint-5-plan.md, which owns their
scope; their issue numbers live on the parent issue #104. This record names the exact part of a
split ticket (B6a or B6b, never B6). Why: each part has its own worker, and a worker executes only
the rows that carry its own id.

## Binding rules

1. A failing test is a bug unless this record lists it as RETIRE or REEXPRESS for the ticket at
   hand, in its Ticket column or in a "Before then" note. Fix the code; do not edit, skip,
   deselect or xfail the test. Why: this is the clause CLAUDE.md carries for sprint 5, and it is
   what keeps the record closed.
2. Retire a test only in the ticket named here, in the PR that deletes what the test exercises or
   makes it unreachable, and only after its replacement is live. Why: expand, then contract
   (HANDOFF 2.3), so main keeps a working read and a pattern download at every merge.
3. A re-expressed test keeps its intent and its thresholds; only its inputs, entry path, API
   surface or test module change, as its row says. Where a row changes an expected value, it
   names the hand-computed source (a MATH.md vector, a PATTERN-SPEC.md rule, or a rule its plan
   ticket states, such as A10's square sizes): write that arithmetic in a test comment before the
   implementation. Never turn observed output into an expected value. Why: expected values flow
   one way, from hand computation to assertion (CLAUDE.md).
4. Mechanical edits that change no assertion and no expected value need no entry: an import
   repointed to the symbol's new home, a call retargeted to a renamed function, a test-only helper
   moved into its test. Why: they keep each test's meaning. The import tables below name the
   known cases.
5. A per-file copy-audit id follows its file. web/src/copy-audit.test.ts and
   web/src/copy-audit-verdicts.test.ts generate one test per scanned file under web/src, so
   deleting a file removes its two ids and adding a file adds two. Why: these ids describe files,
   not behavior.
6. tests/golden/ changes only in ticket A6's consolidated [bless] commit (see
   [bless] policy for sprint 5). Why: Jake approved one bless after the math and document bytes
   settle, and no other (HANDOFF 2.6 and 5).
7. Everything else needs an amendment that Jake approves (see Amending this record): a
   retirement not listed here, a changed threshold, an expected value without a named
   hand-computed source, a golden file that [bless] policy item 2 does not name. Overnight, the
   ticket stops and reports BLOCKED. Why:
   HANDOFF 2.6 withholds approval for any bless or retirement this record does not name.
8. Tests added after the recorded commit are outside the record. They stay, and rule 1 covers
   them.

## Provenance and verification

The tables describe the repository at the recorded commit,
834d8be60cbf6f11354c4b5e6fbac5ffd90f6641, the head of main when sprint-5 setup began. Regenerate
or verify them from the repo root with the repo venv:

```
.venv/Scripts/python scripts/rebaseline_inventory.py --check       # exit 0: the tables match
.venv/Scripts/python scripts/rebaseline_inventory.py --write       # rewrite the generated blocks
.venv/Scripts/python scripts/rebaseline_inventory.py --list KEEP   # print one class's ids
```

The script reads only the recorded commit's inputs and refuses (exit 2) when pyproject.toml,
qrep/, tests/, web/src/ or web/e2e/ in the checkout differ from that commit. Once sprint-5 tickets
change those paths, verify against a separate checkout of the recorded commit:

```
git worktree add --detach ../qrep-rebaseline 834d8be60cbf6f11354c4b5e6fbac5ffd90f6641
.venv/Scripts/python scripts/rebaseline_inventory.py --check --repo ../qrep-rebaseline
```

`--check` and `--list` write nothing, and `--write` rewrites only the generated blocks of this
file; the pytest collection runs with bytecode writing and the pytest cache disabled. Exit codes:
0 the tables match (or were written), 1 they differ from a fresh generation, 2 the record cannot
be generated at the recorded commit (for example, the inputs differ from it).

How the classes are derived:

- Python: `pytest --collect-only` lists every node id. Each test function is analysed with `ast`
  for the qrep symbols it reaches: imports, attribute chains, helpers, fixtures, CLI commands, the
  corners or no-corners shape of reverse() and rectify(), asserted diagnostics keys, fixture
  loaders and qrep files read as text.
- Web: vitest and Playwright titles are parsed statically. Titles built in loops come from
  declared expanders that mirror the loop sources. The setup inventory compared these ids with
  `vitest list` (252 ids) and `playwright test --list` (48 ids) at the recorded commit and found
  them identical.
- Every symbol, scanned web file and e2e surface has a declared fate: DELETE, REBUILD, KEEP, MOVE,
  INPUT (an automatic read whose call survives with confirmed corners and counts) or HARNESS. The
  fixed rule ignores HARNESS symbols: subjects that are all DELETE, or DELETE plus INPUT, give
  RETIRE; INPUT or MOVE gives REEXPRESS; otherwise KEEP; any other mix needs an override.
  Declared per-test overrides, each with its reason, settle the rest. The By column says which
  decided a row: `map` (the rule) or `override`.
- KEEP: unaffected by the deletions. RETIRE: exercises only code that sprint 5 deletes.
  REEXPRESS: intent and thresholds kept; inputs, entry path or API surface change as stated.

## Decisions that closed the draft inventory

The setup chat's draft inventory left 42 tests undecided (18 Python, 24 web). This record decides
each one and, on review, moves 25 more: the 15 holds-or-improves palette ceilings retire because
they are observed output (verified review finding tests-11), and 10 tests that pin the v1 booklet
structure, assembly steps or cut layout become re-expressions (PATTERN-SPEC.md GAP-01, GAP-08,
GAP-11, GAP-17). The decisions that shape the most rows:

- Retirements run only in A7, B6b, C6a and C6b, plus C3c for web/e2e/verdicts.spec.ts alone
  (plan section 3.2, item 16). Why: once C3c sends every photo read to Your pattern, no read can
  reach the verdict panel, so the test would fail from C3c until C6b deletes it.
- Math pins move in the ticket that changes their value, to the MATH.md vector the row names.
  Pins on the benchmark fixture move in A6, together with the fixture and the goldens (see
  [bless] policy for sprint 5).
- The legacy byte pins become semantic checks in A8, first on night 1. Why: they store the full
  recovered model, settings included (tests/fixtures/legacy_regression/l0_seed42.json), so A1's
  first new Settings field would fail them. B6b retires test_pin_committed with the pin files.
- detect_repeat stays. The block-consistent vote needs the label period over the confirmed
  blocks: the fixture alternates two 5 x 5 block types, so its label period is 10 x 10.
- The confirm screen has no automatic corner detection and no Reset to auto, and confirmed corners
  always reach the engine (criteria U3-4, U3-5). The synthetic sample photo keeps its bypass
  until C6b removes that path, and C9's examples replace it (criterion U3-9; plan section 5.C,
  decision 2).
- The hand-authored demo quilt stays as See a sample pattern, which opens Your pattern without a
  read (C2a; plan section 5.C, decision 2), so the e2e tests that opened the demo move onto it.
- The Pattern tab leaves with the editor in C6a: strategy cards, the five downloads, copy my
  settings and the print sheet. Your pattern has one Download pattern (PDF) button (HANDOFF 5),
  and its shopping lines carry the yardage table's numbers from the engine summary (C2b; plan
  section 5.C, decision 1).
- bridge.presets() stays. web/src/model/sizing.ts and web/src/shell/PalettePanel.tsx leave in
  C6a, after C2b reads presets() from the bridge and C2a renders the census in
  viewer/FabricsPanel.tsx; their copy-audit ids retire with them.
